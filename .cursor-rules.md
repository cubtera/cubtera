# Cursor Rules for Cubtera Project

## Core Principles
1. Always start with semantic search to understand context
2. Use grep search for exact symbol/function matches
3. Read files before editing
4. Test changes immediately
5. Document significant changes

## Workflow Steps
1. **Context Gathering**
   - Use `codebase_search` for semantic understanding
   - Use `grep_search` for exact matches
   - Read relevant files with `read_file`
   - Check test files for behavior examples

2. **Making Changes**
   - Always read target file first
   - Use `edit_file` for changes
   - Keep edits focused and minimal
   - Add tests for new functionality
   - Update documentation

3. **Testing**
   - Run specific test with `cargo test test_name`
   - Run all tests with `cargo test`
   - Check for warnings and errors
   - Verify integration tests

4. **Documentation**
   - Update doc comments
   - Add examples where needed
   - Document breaking changes
   - Update README if needed

## Project Structure
- `src/core/` - Core functionality
  - `runner/` - Command execution and logging
  - `dim/` - Dimension handling
  - `dlog/` - Logging functionality
- `src/cli/` - CLI interface
- `tests/` - Integration tests

## Key Components
1. **Runner System**
   - Base runner in `src/core/runner/mod.rs`
   - TF runner in `src/core/runner/tf/mod.rs`
   - Logger functionality in both

2. **Dimension System**
   - Core in `src/core/dim/mod.rs`
   - Extensions in `src/core/dim/ext/`
   - Tests in `src/core/dim/tests/`

3. **Logging System**
   - Database logging via `src/core/dlog/mod.rs`
   - File logging in runner
   - Tests in `src/core/runner/logger_tests.rs`

## Common Patterns
1. **Error Handling**
   - Use `Result<T, Box<dyn Error>>`
   - Proper error propagation
   - Context in error messages

2. **Testing**
   - Unit tests in same file
   - Integration tests in `tests/`
   - Mock external dependencies

3. **Configuration**
   - Use `GLOBAL_CFG` for settings
   - Environment variables for secrets
   - File-based config for paths

## Best Practices
1. **Code Style**
   - Follow existing patterns
   - Use clear variable names
   - Add comments for complex logic
   - Keep functions focused

2. **Performance**
   - Avoid unnecessary allocations
   - Use references where possible
   - Cache expensive operations

3. **Security**
   - No hardcoded secrets
   - Validate user input
   - Safe file operations

## Common Commands
```bash
# Run specific test
cargo test test_name

# Run all tests
cargo test

# Run with logging
RUST_LOG=debug cargo test

# Check formatting
cargo fmt

# Check clippy
cargo clippy
```

## Troubleshooting
1. **Test Failures**
   - Check test output
   - Look for error messages
   - Verify test data
   - Check mock behavior

2. **Build Errors**
   - Check dependencies
   - Verify imports
   - Check type signatures
   - Look for missing traits

3. **Runtime Errors**
   - Check error messages
   - Verify file paths
   - Check permissions
   - Look for missing files
